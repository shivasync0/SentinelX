# SENTINEL X 3–5 minute demo

## Flow

1. Open `/` and point out the evidence-first value proposition.
2. Click **Enter command center**. The seeded brands, official assets, candidate
   inventory, and source labels are loaded from the API.
3. Click **Run demo scan**. Explain that the scan is deterministic and synthetic.
4. Open **Discovery**. Show the official Acme Security domain marked `Verified` and
   excluded before scoring.
5. Open **Acme Secur1ty**. Read the look-alike name, unapproved domain, and surface
   signals in the evidence drawer.
6. Open **Social intelligence** and **App intelligence** to show the separate
   candidate categories and their fixture provenance.
7. Open **Threat graph**. Select the two Acme candidates linked through
   `acme-security-login.com`; explain that the edge is a stored shared-domain fact,
   not an attribution claim.
8. Create an investigation, add analyst context, and link the candidates.
9. Expand the case, mark it `in_progress`, and generate an evidence report. Use the
   report's JSON download or print action.
10. Open **Source health** and point out the explicit demo/unverified status.

## Five-slide outline

1. **Problem:** brand impersonation is fragmented across social, domains, and apps.
2. **Product:** registered identity plus official-asset exclusion before alerting.
3. **Differentiator:** explainable signals and an evidence-backed relationship graph.
4. **Demo:** scan → candidate evidence → graph → investigation → report.
5. **Honest roadmap:** live permitted adapters, image similarity, authentication, and
   calibrated evaluation datasets.
